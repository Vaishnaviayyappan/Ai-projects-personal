# App Company OS

A web app version of the "$100M AI App Company" framework: submit one app idea and get a
Final App Launch Plan generated by six agent perspectives (Customer, Product, UX, AI
Strategy, Monetization, Growth) that build on each other and end in a
BUILD / CHANGE / VALIDATE FIRST recommendation.

Built with Next.js (App Router, TypeScript), an open-source model (Llama 3.3) hosted on
[Groq](https://groq.com)'s free tier for the generation, and a local SQLite database (via
`better-sqlite3`) that saves every run to a browsable history.

Groq was chosen over running a model locally because this app asks a lot of a model (seven
structured steps ending in a fourteen-field launch plan) and CPU-only local inference is
impractically slow on most laptops — Groq runs the same class of open-source models on
dedicated inference hardware, so a full run typically finishes in well under a minute.

## Setup

1. **Get a free Groq API key** — sign up at [console.groq.com](https://console.groq.com),
   create a key under **API Keys**. The free tier needs no payment info.
2. **Install dependencies**:
   ```bash
   npm install
   ```
3. **Add your key**: copy `.env.example` to `.env.local` and paste your key in:
   ```bash
   cp .env.example .env.local
   ```
   ```
   GROQ_API_KEY=gsk_...
   ```
   Optionally set `GROQ_MODEL` to a different model from Groq's catalog.
4. **Run it**:
   ```bash
   npm run dev
   ```
   Open [http://localhost:3000](http://localhost:3000).

Without step 3, the app runs fine but every "Build my launch plan" click returns a clear
"no API key configured" message instead of calling Groq.

## How it works

- `src/lib/prompt.ts` — the Master Prompt pipeline (the same seven-step agent sequence from
  the original framework) and the six standalone agent prompts shown for reference on the
  home page.
- `src/app/api/generate/route.ts` — a server route that builds the full prompt from the
  submitted idea, streams the answer back from Groq's OpenAI-compatible chat completions
  endpoint over Server-Sent Events, and saves the finished plan to SQLite. It also cancels
  the upstream Groq request if the client disconnects (Stop button, closed tab), instead of
  leaving it to finish generating for no one.
- `src/components/IdeaBuilder.tsx` — the client-side form + live streaming results panel.
- `src/app/history/` — a list of every past run and a detail page per run, reading directly
  from the SQLite database.

Local history lives in `data/app.db` (gitignored) — delete that file to reset history.

## Deploying

This app needs a Node.js server (not a static host) because of the streaming API route and
the SQLite file. It runs well on any Node hosting platform with a persistent disk (a small
VPS, Render, Fly.io, Railway, etc.):

```bash
npm run build
npm run start
```

Set `GROQ_API_KEY` (and optionally `GROQ_MODEL`) as environment variables on whatever
platform you deploy to. If you deploy somewhere with an ephemeral filesystem (e.g. Vercel's
serverless functions), the SQLite history will not persist between deploys/instances — swap
`src/lib/db.ts` for a hosted database (Postgres, Turso, etc.) in that case.

## Disclaimer

"$100M" is creative branding, not a valuation or a promised result. The six agent personas
are inspired by publicly available ideas and frameworks associated with the people
referenced in the original guide; they are not affiliated with, endorsed by, or trained by
those people, and the app never has the model speak as or quote them. Treat every number in
a generated plan as `DATA NOT PROVIDED`, a fact you supplied, or `[TO BE MEASURED]` —
validate with real users before building anything.
